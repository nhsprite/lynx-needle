# lynx-needle (AI Guide)

## What this project is

A Lynx AutoLink NAPI addon that embeds Cactus Needle 2 (a 45M-parameter, 2-bit
on-device tool-calling model) into Lynx pages on Android and iOS. Deliverables:

- the `lynx-needle` npm package (`packages/lynx-needle/package.json`): a thin
  TypeScript frontend API (`loadNeedle()` / `createNeedle()`)
- client SDKs: `packages/lynx-needle/android/` (AutoLink Gradle library module) and `packages/lynx-needle/ios/`
  (AutoLink CocoaPods pod) with the platform glue that lets a Lynx host load
  the addon
- `examples/`: `android-host`, `ios-host`, `lynx-needle-demo` (frontend)

The native addon is built by cross-platform CMake with branches for Android,
iOS, and macOS. HarmonyOS is intentionally out of scope because the Needle
engine does not publish an OHOS static library.

## Critical constraint: NAPI needs Lynx ≥ 4.3.0 (nightly) or a source build

The Lynx NAPI module loader requires a runtime built with
`enable_napi_binding=true`. The **4.3.0 nightly snapshots** are the first
published artifacts with it:

- Android: use the Maven Central snapshot repository
  (`https://central.sonatype.com/repository/maven-snapshots/`), validated with
  `4.3.0-nightly.202609080610.178.gcd26ecb7-SNAPSHOT`.
- iOS: use `https://github.com/lynx-family/Specs.git`, validated with
  `4.3.0-nightly.202609090610.180.g5e30c9e6`. The podspec downloads its zip
  from `artifacts-storage.tos-s3-ap-southeast-1.bytepluses.com`; it is not on
  CocoaPods Trunk.

Against a runtime without NAPI binding, `loadNeedle()` returns `null` by design.

## Quick start

```bash
npm install && npm run fetch-engine   # engine static libs + weak-node-api headers
npm run build                         # npm package: tsc src/ -> lib/
npm run build:android                 # -> packages/lynx-needle/android/src/main/jniLibs/<abi>/*.so
npm run build:ios                     # -> packages/lynx-needle/build/ios-{device,sim}/out/libNeedle.a + pod artifacts
npm run build:macos                   # -> packages/lynx-needle/build/macos/out/libneedle.a
```

## Output naming

- Android: `packages/lynx-needle/android/src/main/jniLibs/<abi>/lib<project>.so` (+ `libnapi_adapter.so`) — written directly into the package's AAR module, no sync step
- iOS: `packages/lynx-needle/build/ios-device/out/lib<project>.a` or `packages/lynx-needle/build/ios-sim/out/lib<project>.a`
- macOS: `packages/lynx-needle/build/macos/out/lib<project>.a`
- Darwin packaging: `packages/lynx-needle/ios/<project>.xcframework`, `packages/lynx-needle/ios/<project>.podspec`, and `packages/lynx-needle/ios/addon_use.h` after `npm run package:darwin`

## Repository layout

- `packages/lynx-needle/src/` — npm package source (TypeScript): `index.ts` is the entry barrel, `needle.ts` the implementation; `npm run build` (tsc) emits `packages/lynx-needle/lib/`
- `packages/lynx-needle/cpp/` — legacy standalone addon sources kept for macOS/local experiments
- `packages/lynx-needle/shared/nativeModule/` — shared AutoLink NAPI implementation and generated registration
- `packages/lynx-needle/android/` — Android AutoLink library module (AAR): CMake source build + jniLibs outputs
- `packages/lynx-needle/ios/` — iOS AutoLink pod: generated wrapper, `addon_use.h`, podspec, and xcframework outputs
- `examples/` — `android-host`, `ios-host`, `lynx-needle-demo` (frontend)
- `packages/lynx-needle/lib/`, `packages/lynx-needle/build/` — generated (gitignored): tsc output and cmake build trees

## Editing the frontend API

- Edit `packages/lynx-needle/src/needle.ts`; re-export new modules from `packages/lynx-needle/src/index.ts` so the
  package's `main`/`exports` (`lib/index.js`) stay stable.
- Run `npm run build` after changes — consumers using the local
  `file:<repo>/packages/lynx-needle` dependency (e.g. `examples/lynx-needle-demo`) read `packages/lynx-needle/lib/`,
  and `file:` deps do not trigger `prepack`.

## Editing addon code

- Implement shared mobile NAPI logic in `packages/lynx-needle/shared/nativeModule/Needle.cc`; keep
  `packages/lynx-needle/shared/nativeModule/generated/NeedleRegistration.cc` and `packages/lynx-needle/ios/addon_use.h`
  generated by `npm run codegen`.
- If you enable `USE_WEAK_SUFFIX_NAPI`, follow the per-translation-unit include convention:
  - include `weak_napi_defines.h` after the last include
  - include `weak_napi_undefs.h` at the end of the file

## Platform linking strategy

- Android: the AutoLink Gradle/CMake build extracts PrimJS native libraries from the Lynx nightly AAR, then links and stages `libNeedle.so`, `libnapi.so`, and `libnapi_adapter.so` into jniLibs.
- Windows: coming soon.
- iOS: the pod emits a static xcframework plus a generated `addon_use.h`
  header. The generated CocoaPods AutoLink registry includes that header,
  installs the PrimJS weak Node-API provider, and invokes the addon's register
  symbol. Host app code should not register `LynxNodeAPI` manually.
- macOS: local standalone builds still use the package CMake target.

## Darwin packaging

- Build the required Darwin static library slices first, then run `npm run package:darwin`.
- The packaging script (`packages/lynx-needle/scripts/package-darwin.mjs`) picks the iOS `.a` slices
  from `packages/lynx-needle/build/<dir>/out/`, creates a local-consumable
  podspec that points to the generated xcframework, and writes
  `packages/lynx-needle/ios/addon_use.h`.
- For remote publishing, replace the generated podspec source stanza with your hosted zip URL and checksum.
